# Estate VOI R0.3 Governed Transitions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist Estate Proposition and Deal records, bind qualified possibilities to integrity-checked VOI inventory evidence, and require Warden/River governance references before a governed execution intent can be recorded.

**Architecture:** Extend `EstateRegistry` without enabling any operational connector. Evidence bundles are registered by verified bundle identity; Propositions reference registered evidence; Deals require acceptance evidence plus Warden/River transition references; Execution Intents require a Deal, Warden decision, River receipt and idempotency key and remain non-executing local records.

**Tech Stack:** Python 3.11, sqlite3, dataclasses, hashlib/json, unittest, existing Streamlit portal.

**Spec:** `docs/ESTATE-VOI-R0.2.md`

## Global Constraints

- Preserve `EST-POS -> EST-PROP -> EST-DEAL -> governed execution intent -> EST-REAL` semantics.
- No Logic ERP, Easycom, marketplace, warehouse or factory mutation.
- Only `VOI-INVENTORY-EVIDENCE-001` / `READ_ONLY_EXPORT` bundles may be registered in this slice.
- Verify evidence bundle SHA-256 integrity before persistence.
- A Proposition requires a persisted `QUALIFIED` possibility and a registered evidence bundle.
- A Deal requires explicit commercial acceptance evidence, a Warden decision reference and a River receipt reference.
- An Execution Intent requires a Deal, Warden decision reference, River receipt reference and non-empty idempotency key.
- Execution Intent is not operational execution and creates no external effect.
