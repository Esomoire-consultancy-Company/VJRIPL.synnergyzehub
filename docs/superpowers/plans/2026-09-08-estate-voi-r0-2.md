# Estate VOI R0.2 Registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an Alpha-grade persistent Estate Possibility Registry and VOI Capability Ledger with commercial guardrails, expiry/requalification, reservation-conflict detection, evidence references, and a read/write Estate Board limited strictly to Estate-local records.

**Architecture:** Extend the R0.1 lifecycle with a standard-library SQLite repository. `estate_registry.py` owns persistence and commercial-control decisions; `estate_board.py` presents the Streamlit control surface. Existing Logic ERP, Easycom, marketplace, warehouse, factory, Warden and evidence components remain external authorities and are never mutated by this slice.

**Tech Stack:** Python 3.11, sqlite3, dataclasses, JSON, Streamlit, unittest.

**Spec:** `docs/ESTATE-VOI-R0.1.md`

## Global Constraints

- VOI/Voyej remains `VOI-CLIENT-001`.
- Preserve canonical lifecycle `EST-POS -> EST-PROP -> EST-DEAL -> EST-REAL` from R0.1.
- Do not write to Logic ERP, Easycom, Myntra, Flipkart, Centro, warehouse or factory systems.
- Do not treat Estate-local reservation as operational inventory reservation.
- Store external observations only as evidence references/provenance.
- SQLite is Alpha/local persistence only; production multi-writer storage is out of scope.
