# VJRIPL / VOI Synnergyze Hub

**Matter ID:** `MAT-VJRIPL-001`

This repository is a governed engineering Matter for VJRIPL / VOI-related product, commercial, evidence and Estate work. It contains a mixture of current Matter capability, historical prototypes, external/public-source dependencies, reusable platform concepts and legacy material whose provenance may still be under review.

- an authoritative production system merely because code is present;

- a grant of production credentials or external-system authority;
- proof that every artifact is legally owned by VJRIPL / VOI or by Synnergyze/Esomoire;

## Publication posture

The prospective Matter model separates:

- **`RESTRICTED_WORKING_MATTER`** — the complete working/client engineering record; and
- **`PUBLIC_QUALIFIED_PROJECTION`** — a deliberately prepared, reviewed and bounded public release.

Public visibility of a GitHub repository does not by itself classify every contained artifact as public-qualified, resolve confidentiality, determine IP ownership, or define licence scope.

No repository-wide `LICENSE` is introduced by the current governance disposition. Any future licence or publication decision must identify the exact rights, scope, version, authority and affected Matter classes.

## Legacy / prototype warning

Legacy Buying House, product/order, merchandiser, retailer/stock-analysis and simulated production surfaces are governed as prototype/research material unless separately admitted. Sample SKUs, prices, MOQs, timelines, personas, contact details and generated metrics must not be interpreted as current VOI operational truth.

Unresolved legacy images, documents, archives and task-master assets remain subject to provenance review and are not approved for new intentional republication solely because they exist in repository history.

## VOI evidence capability

The later VOI Inventory Evidence work is separately governed from the legacy prototype shell. Evidence integrity, validation and source fingerprints do not create execution authority: **evidence is not authorization**.

## Contributions and Matter changes

Use the Matter-native Issue and pull-request templates. Material changes should state:

- Matter Issue / purpose;
- attributable VJRIPL / VOI benefit;
- IP/provenance class;
- cross-Matter imports or `none`;
- evidence/validation;
- authority boundary;
- supersession or `none`;
- operational-effect state.

Do not add client operational exports, credentials, private contractual records or unresolved third-party/client assets to a public branch merely to support a review. Use controlled evidence references instead.
